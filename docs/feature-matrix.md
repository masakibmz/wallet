## 20. 补全顺序（推荐）

与产品优先级对齐，**不推翻现有分层**，在现有 Repository/Service 上扩展。

### P0：核心账务正确性（必须先测后 UI）

1. 余额引擎：信用卡负债/溢缴款、还款、退款回冲、手续费/优惠券对余额与统计一致  
2. 退款：Repository 完善 + 单测 + 与原单关联 UI  
3. 转账/信用卡还款：专用流程 + 双账户校验 + 测试  
4. 报销：状态机 + 流水关联  
5. 债务/分期/周期：Repository + 自动生成 Job + 单测（再接入 UI）  
6. 补写：`RefundRepository` / 扩展 `TransactionRepository` 测试

### P1：核心 UI（钱迹主路径）

1. 完整记账页（标签/手续费/优惠券/报销/附件）  
2. 账单：筛选 + 批量编辑/删除  
3. 资产：账户 CRUD、排序、隐藏、详情、信用卡视图  
4. 分类/标签：完整管理（图标、排序、编辑）  
5. 预算：设置 + 首页/统计联动  
6. 搜索：组合条件 UI +（可选）Drift 查询优化  
7. 日历：月历 + 日详情 + 点击记账  
8. 账本：新建/编辑/删除/切换

### P2：数据能力

1. CSV 导入 + 预览/映射/重复检测  
2. 微信/支付宝/钱迹/Excel 解析器（独立 Service）  
3. 附件存储（路径引用 + 预览）  
4. 多币种：汇率 Repository + 换算 + 资产折合本位币

### P3：iOS

1. 冷启动 App 锁 + PIN  
2. Liquid Glass 与原生 Navigation/Tab 对齐 iOS 26 设计  
3. Widget Extension + App Group 读摘要  
4. Shortcuts  
5. Haptic/Sheet/Context Menu 统一封装

### P4：高级

1. AI：真实 Parser Provider + 确认页字段可编辑  
2. SyncRecord 写入 + SyncRepository 实现 + 冲突策略  
3. 共享账本（`sharedLedgerId` 协议）

## 21. 架构问题（审计发现）

1. **表多 Repository 少**：10+ 表无访问层，易出现「Schema 驱动假象进度」。  
2. **`Transfers` 表冗余**：转账仅体现在 `Transactions.type`，独立表未使用。  
3. **`CategoryGroups` 未用**：分类扁平 `parentId` 够用但未与钱迹分组对齐。  
4. **Provider 分散**：`budgetRepositoryProvider` 在 `settings_page.dart`，应归拢 `application/providers`。  
5. **无 Sync 出站**：本地变更未写 `SyncRecords`，未来同步需横切拦截。  
6. **搜索全量内存过滤**：账本增长后性能与钱迹体验不符。  
7. **迁移未验证**：仅 v1，后续功能增字段需补 migration 测试。  
8. **iOS 目标与 Windows 预览混用**：Cupertino 降级合理，但 Tab/Nav 与钱迹原生仍有差距。  
9. **测试策略偏单元**：核心财务有单测，**无 Repository 级与 Widget 级**，回归风险高。  
10. **Onboarding 幂等**：仅有分类则跳过种子，旧库可能缺账户/分类不一致（运维/迁移需处理）。
